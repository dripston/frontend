# Hackathon

A production-grade [Next.js](https://nextjs.org) 16 starter: strict TypeScript, validated
environment, hardened headers, and a standalone server build.

## Requirements

| Tool | Version                                  |
| ---- | ---------------------------------------- |
| Node | 24 (see `.nvmrc`; anything ≥ 20.9 works) |
| pnpm | 9+ (`corepack enable`)                   |

## Getting started

```bash
pnpm install
cp .env.example .env.local
pnpm run dev
```

The app runs at http://localhost:3000.

## Scripts

| Script              | What it does                                   |
| ------------------- | ---------------------------------------------- |
| `pnpm dev`          | Dev server with hot reload                     |
| `pnpm build`        | Production build (`.next/standalone`)          |
| `pnpm start`        | Serve the production build                     |
| `pnpm typecheck`    | `tsc --noEmit`                                 |
| `pnpm lint`         | ESLint, zero warnings tolerated                |
| `pnpm lint:fix`     | ESLint with autofix                            |
| `pnpm format`       | Prettier write                                 |
| `pnpm format:check` | Prettier check, no writes                      |
| `pnpm test`         | Unit tests once                                |
| `pnpm test:watch`   | Unit tests in watch mode                       |
| `pnpm validate`     | format + lint + typecheck — run before pushing |

## What makes this production-grade

**Type safety.** `strict` plus `noUncheckedIndexedAccess`, `noImplicitOverride`,
`noUnusedLocals` and `noUnusedParameters`. `typedRoutes` checks every `<Link href>` at
compile time, generated by `next typegen`. `next.config.ts` refuses to build past a type
error. Next.js 16 removed the `eslint` build key, so linting runs from `pnpm lint` and the
pre-commit hook rather than as part of `next build`.

**Environment validation.** `src/env.ts` parses `process.env` through Zod at startup, so a
missing variable fails immediately with a readable message instead of surfacing as
`undefined` mid-request. A Proxy throws if server-only variables are read from client code.

**Security headers.** HSTS, `nosniff`, `X-Frame-Options`, `Referrer-Policy`,
`Permissions-Policy` and COOP are static in `next.config.ts`. The Content-Security-Policy is
set in `next.config.ts`. See SECURITY.md for why it uses `'unsafe-inline'` rather than a
nonce, and how to switch.

**Testing.** This repo does not carry tests — see rule 6 in AGENTS.md. The Vitest harness is
configured and passes with zero tests, so it is ready if that changes. Verify work with
`pnpm run validate`, `pnpm run build`, and by exercising the path in the browser.

**Checks.** `pnpm run validate` runs format, lint and typecheck in one pass, and
the git hooks run the same checks before a commit or push. There is no CI workflow in this
repo — wire one up to `pnpm run validate` and `pnpm run build` when you want one. Dependabot config is still present and batches updates by ecosystem.

**Container.** Multi-stage build on the standalone output, running as a non-root user with a
`HEALTHCHECK` wired to `/api/health`.

## shadcn/ui

Components are generated into `src/components/ui` and are **yours** — edit them directly, no
wrapper layer and no upstream package to fight. Config lives in `components.json`.

```bash
pnpm dlx shadcn@latest add <component>
```

Built on **Base UI** (`@base-ui/react`), the successor to Radix from the same team. The main
difference from older shadcn code you will find online: composition uses a `render` prop
instead of `asChild`.

```tsx
<Button render={<Link href="/dashboard" />}>Dashboard</Button>
```

Theming is CSS variables in `src/app/globals.css`: `:root` and `.dark` define the raw tokens,
and `@theme inline` maps them to Tailwind utilities (`bg-background`, `text-muted-foreground`).
Change a colour in one place and it propagates everywhere. `--font-sans` and `--font-mono` are
wired to the `next/font` Geist variables set in the root layout.

Currently installed: button, card, input, label, badge, separator, dialog, dropdown-menu,
skeleton, sonner.

## Environment variables

Declare every variable in `src/env.ts`, then document it in `.env.example`. Anything not in
the schema is ignored.

- Server-only variables go in `serverSchema` and never reach the browser. Reading one from
  client code throws instead of silently yielding `undefined`.
- Browser-visible variables need the `NEXT_PUBLIC_` prefix and go in `clientSchema`. They are
  inlined into the client bundle at build time — never put a secret there.
- Add the key to the `processEnv` map in `src/env.ts` as well. Next.js only inlines
  `process.env.X` when it can see the member access literally, so a dynamic
  `process.env[key]` lookup will not work.
- `SKIP_ENV_VALIDATION=1` bypasses validation for image builds that have no runtime secrets;
  the container still validates on boot.

## Auth and database

Better Auth on Neon Postgres via Drizzle.

```
src/lib/db/schema.ts    Drizzle tables (user, session, account, verification)
src/lib/db/index.ts     Neon HTTP driver + Drizzle instance (server-only)
src/lib/auth.ts         Better Auth server config (server-only)
src/lib/auth-client.ts  React client — signIn, signUp, signOut, useSession
src/app/api/auth/       Catch-all route handler
drizzle/                Generated migrations, committed
```

First-time setup:

1. Create a Neon project and copy the **pooled** connection string.
2. Put it in `.env.local` as `DATABASE_URL`, and add
   `BETTER_AUTH_SECRET` (`openssl rand -base64 32`).
3. Apply the schema: `pnpm run db:migrate`.

| Script             | What it does                                  |
| ------------------ | --------------------------------------------- |
| `pnpm db:generate` | Write a migration from schema changes         |
| `pnpm db:migrate`  | Apply pending migrations                      |
| `pnpm db:push`     | Push the schema directly, skipping migrations |
| `pnpm db:studio`   | Open Drizzle Studio                           |

Email and password sign-in works out of the box. GitHub and Google are registered only
when both the client id and secret are set, so the buttons return a clear error until you
configure them.

The schema is not hand-invented: it mirrors `getAuthTables()` from the installed Better Auth
version. If you upgrade Better Auth, re-check that output before trusting the existing
tables — `account.issuer`, for instance, only appeared in 1.7.

## Deploying to Render

`render.yaml` describes a native Node web service — no container involved. Point Render at
this repo as a Blueprint, or create a web service manually with:

- Build command: `corepack enable && pnpm install --frozen-lockfile --prod=false && pnpm run build`
- Start command: `pnpm start`
- Health check path: `/api/health`

`pnpm start` runs `.next/standalone/server.js`, which honours Render's `PORT` and binds
`0.0.0.0`.

Every variable marked `sync: false` in `render.yaml` must be filled in from the Render
dashboard before the first deploy. `NEXT_PUBLIC_*` values are inlined at build time, so
`NEXT_PUBLIC_APP_URL` has to hold the real public origin — changing it later needs a rebuild,
not just a restart.

## Git hooks

Husky runs on `pnpm install`:

- **pre-commit** — lint-staged formats and lints staged files.
- **commit-msg** — commitlint enforces [Conventional Commits](https://www.conventionalcommits.org)
  (`feat:`, `fix:`, `docs:`, …).
- **pre-push** — typecheck.

Bypass with `--no-verify` only when you have a specific reason.

## Optional Next.js 16 features

Both are off by default because they change build behaviour; enable deliberately.

- **Cache Components** — set `cacheComponents: true` in `next.config.ts` for `use cache` and
  Partial Prerendering. Data fetching becomes dynamic by default and pages need Suspense
  boundaries around dynamic reads.
- **React Compiler** — `pnpm add -D babel-plugin-react-compiler`, then `reactCompiler: true`.
  Removes most manual `useMemo`/`useCallback` at the cost of slower builds.

## Notes

TypeScript is pinned to 5.9 rather than 7.x: the 7.0 native compiler is released, but the
lint toolchain here has not certified against it yet. Revisit once `typescript-eslint`
declares support.
